# tetro-term

ターミナルで動く落ち物パズル。Go で書かれていて、**同じコードが CLI とブラウザの両方で動く**。

ブラウザ版は Go を WebAssembly にコンパイルし、その端末出力を
[xterm.js](https://xtermjs.org/) がそのまま描画している。
つまりブラウザに見えているのは端末エミュレータの画面そのもの。

🎮 **[ブラウザで遊ぶ](https://bubbleshaker.github.io/tetro-term/)**
（キーボードのある端末向け。スマートフォンのタッチ操作は M3）

## ターミナルで遊ぶ

```sh
go run ./cmd/tetro
```

落ちて・積んで・消えるところまで遊べる。スコアとレベルはまだ無い（M7）。

## 操作

| キー | 動作 | |
| --- | --- | --- |
| `←` `→` | 左右に移動 | ✅ |
| `↓` | ソフトドロップ | ✅ |
| `↑` | 右回転 | ✅ |
| `z` | 左回転 | ✅ |
| `q` / `Ctrl-C` | 終了（CLI 版のみ） | ✅ |
| `Space` | ハードドロップ | M4 |
| `c` | ホールド | M5 |

壁際で回すと引っかかることがあるのは、ウォールキックがまだ入っていないため（M6）。

ブラウザ版に「終了」は無い。プロセスの終わりが存在しないため、`q` と `Ctrl-C` は
何もしない。ゲームオーバーからのやり直しはリロードで行う（リスタートは M7）。

スマートフォンでは画面下のボタンで操作する（M3）。

ブラウザ版は**タブを背面にすると止まる**。時間を測っているのが
`requestAnimationFrame` で、これは見えていないタブでは動かないためである。
戻ってくると止まったところから続きが始まる。

### 押しっぱなしの移動について

端末も xterm.js も「キーが離された」ことをアプリに伝えてくれないため、
押しっぱなしの連続移動は **OS のキーリピート設定に委ねている**。
移動が遅い・速すぎると感じる場合は OS 側のキーリピート設定を調整してほしい。
