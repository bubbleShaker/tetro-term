# コアと表示の境界を ANSI フレーム文字列にする

同じゲームをターミナル（CLI バイナリ）とブラウザ（`GOOS=js GOARCH=wasm`）の両方で動かすにあたり、
コアが外へ何を渡すかを決める必要があった。**コアは ANSI エスケープを含んだ描画済み文字列
（→ CONTEXT.md「フレーム」）を吐き、CLI はそれを標準出力へ、ブラウザは xterm.js へ流し込む**ことにした。
xterm.js は本物の端末エミュレータなので、ブラウザに出ているのは端末出力そのものになる。

## 考えた代替案

コアが盤面の状態（セル配列など）だけを返し、ANSI レンダラと DOM/Canvas レンダラを別々に書く案。
こちらの方が表示の自由度は高いが、**レンダラを 2 つ保守することになる**。
このプロジェクトの主目的は Go の学習であってブラウザ描画の作り込みではないため、
レンダラを 1 つに畳んでゲームロジックに時間を使う方を選んだ。

## 引き受けた帰結

- ブラウザ側の見た目は「文字グリッド」に固定される。滑らかなアニメーションや
  ピクセル単位の演出はやらない。やりたくなったらこの決定ごと覆すことになる。
- 逆に、**この境界を跨ぐものは文字列だけ**なので、コアは `syscall/js` にも
  端末にも一切依存しない。コアのテストは文字列の比較だけで書ける。
