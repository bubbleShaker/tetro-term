# tetro-term

ターミナルで動く落ち物パズル。Go で書かれていて、**同じコードが CLI とブラウザの両方で動く**。

ブラウザ版は Go を WebAssembly にコンパイルし、その端末出力を
[xterm.js](https://xtermjs.org/) がそのまま描画している。
つまりブラウザに見えているのは端末エミュレータの画面そのもの。

🎮 **[ブラウザで遊ぶ](https://bubbleshaker.github.io/tetro-term/)**
（スマートフォンでは画面下のボタンで操作できる）

## ターミナルで遊ぶ

```sh
go run ./cmd/tetro
```

落ちて・積んで・消えるところまで遊べる。スコアとレベルはまだ無い（M7）。

## 操作

| キー | 動作 | |
| --- | --- | --- |
| `←` `→` | 左右に移動 | ✅ |
| `↓` | ソフトドロップ | ✅ |
| `↑` | 右回転 | ✅ |
| `z` | 左回転 | ✅ |
| `q` / `Ctrl-C` | 終了（CLI 版のみ） | ✅ |
| `Space` | ハードドロップ | M4 |
| `c` | ホールド | M5 |

壁際で回すと引っかかることがあるのは、ウォールキックがまだ入っていないため（M6）。

ブラウザ版に「終了」は無い。プロセスの終わりが存在しないため、`q` と `Ctrl-C` は
何もしない。ゲームオーバーからのやり直しはリロードで行う（リスタートは M7）。

## スマートフォンで遊ぶ

画面下にボタンが出る。左の親指に `←` `↓` `→`、右の親指に `↺` `↻`。
どのボタンをどこに出すかを決めているのは Go 側（`internal/input`）で、
ブラウザはそれを並べているだけなので、キーの割り当てとボタンが食い違うことがない。

`←` `→` `↓` は**押しっぱなしで連続移動する**。回転は押しっぱなしにしても
1 回しか回らない（指を置いている間ずっと回ると、狙った向きで止められないため）。

タッチで操作している間はソフトキーボードを出さない。xterm.js のフォーカス先は
隠れたテキストエリアなので、そこに触れると画面の下半分がキーボードに占領されてしまう。

ブラウザ版は**タブを背面にすると止まる**。時間を測っているのが
`requestAnimationFrame` で、これは見えていないタブでは動かないためである。
戻ってくると止まったところから続きが始まる。

### 押しっぱなしの移動について

端末も xterm.js も「キーが離された」ことをアプリに伝えてくれないため、
キーボードでの連続移動は **OS のキーリピート設定に委ねている**。
移動が遅い・速すぎると感じる場合は OS 側のキーリピート設定を調整してほしい。

タッチボタンには「離した」が取れるので、そちらの繰り返しはブラウザ版の
ドライバ（`web/main.js`）が自分で作っている。

## 開発

設計と段取りは [`PLAN.md`](./PLAN.md)、用語は [`CONTEXT.md`](./CONTEXT.md)、
覆すのが高くつく決定は [`docs/adr/`](./docs/adr/) にある。

```sh
go test ./...                        # コアのテスト
go run ./cmd/tetro                   # CLI 版
./scripts/build-wasm.sh              # ブラウザ版をビルド
node scripts/check-touch.mjs         # タッチ操作を実際に触って確かめる（playwright が要る）
```

`scripts/check-touch.mjs` は CI に入れていない。Go のリポジトリに node_modules と
ブラウザを引き込む割に合わないので、手元で回す道具として置いてある。
詳しくはスクリプト冒頭のコメントを参照。
