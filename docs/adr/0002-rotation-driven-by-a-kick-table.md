# 回転処理をキックテーブル駆動にし、表は後から差し替える

壁際でミノを回転させると盤面や既存のセルにめり込むため、位置をズラして回転を成立させる
（ウォールキック）必要がある。現代の標準である SRS は「ミノの種類 × 回転の向き」ごとに
5 通りのズラし候補を順に試す、という**表**として定義されている。

**回転処理は「候補オフセットの列を順に試し、最初に成立したものを採用する」という形だけを実装し、
候補の中身はデータ（→ CONTEXT.md「キックテーブル」）として外に置く**ことにした。
最初は候補を `{(0,0)}` の 1 個だけにしておく（＝キックなし）。後から SRS の表を流し込めば、
アルゴリズムに手を入れずに挙動が本格化する。

## なぜこうしたか

最初から SRS を完全実装するのは初手として重く、かといってキックなしで作り込むと
後で回転処理そのものを書き直すことになる。アルゴリズムとデータを分けておけば、
M1 の実装量を抑えたまま M6 で表を差し込むだけで済む。
「アルゴリズムとデータを分離する」練習になること自体も、学習目的に照らして狙いのうち。
